# 設計書：薬局の受付画面の追加機能（QRチラシ・パスワード再設定・ご意見・運営の管理画面）

作成日：2026-11-05　／　前提：`2026-11-01-pharmacy-ab-plans-design.md`（プランA・B、本番稼働中）、
同日のプラン選択（薬局が受付画面でプランを選ぶ、本番稼働中）
承認：オーナー（2026-11-05、チャットで4機能と方式を選択）

## 1. 目的

今は運営が手作業でしていることを、画面でできるようにする。お試しの薬局が増えても運営の手間が増えないように。

| 機能 | 今 | これから |
|---|---|---|
| 窓口のQRチラシ | 運営が薬局コードを入れて作って送る | 薬局（B・AB）が受付画面から印刷する |
| パスワードを忘れたとき | 方法がない | 薬局がログイン画面からメールで再設定。運営も管理画面からリンクを発行できる |
| ご意見 | メール・聞き取り | 受付画面から送る。管理画面に集まり、運営にメールでお知らせ |
| 薬局の登録・プラン・利用状況 | スクリプト（new-pharmacy.mjs など） | 運営の管理画面（rxhelper.jp/admin） |

## 2. 各機能

### 2.1 窓口のQRチラシ（B・AB）
- 受付画面に「QRチラシを印刷」。開くと、既存の `docs/pilot/窓口案内チラシ_印刷用.html` と同じ文面・レイアウトのA4チラシに、
  薬局名と、その薬局のQRコード（`https://rxhelper.jp/send?ph=<薬局コード>`）が入ったものを表示し、「印刷する」で印刷。
- QRコードはブラウザの中で作る（ライブラリ `qrcode`）。サーバーには何も送らない。
- 文面は患者さん向けの既存のもの（金銭的な特典・「無料」は書かない）。プランAでは表示しない。
- プラン選択画面のBの注意書きは「受付画面から印刷できます」に変える。

### 2.2 パスワードの再設定
- ログイン画面に「パスワードを忘れた方」。登録のメールアドレスを入れると、**1時間有効**の再設定リンクをそのアドレスに送る
  （Resend、既存の `sendPasswordResetEmail`、日本語）。リンク先は既存の初回設定画面（`/pharmacy/setup`）。
- 登録があってもなくても同じ返事（アドレスの有無を知られない）。IPごとの回数制限（既存の認証の制限）＋アドレスごと1日5回。
- パスワードを設定したら、その薬局のほかのログインはすべて終了する（なりすましの継続を防ぐ）。
- 運営は管理画面から新しい初回設定リンク（14日間有効）を発行できる（メールが届かないとき用）。

### 2.3 ご意見
- 受付画面に「ご意見を送る」。自由記述（2,000字まで）。画面に「患者さんの氏名など個人が分かることは書かないでください」。
- D1 の `pharmacy_feedback` に保存。運営のアドレス（`OPERATOR_EMAIL`、wrangler.jsonc の vars）にメールでお知らせ（薬局名・プラン・本文）。
- 薬局ごと1日20件まで。

### 2.4 運営の管理画面（rxhelper.jp/admin）
- 入り方：**管理者キー**（長いランダムな文字列）。サーバーの秘密値 `ADMIN_TOKEN` と照合。画面で一度入れると、その端末のブラウザに保存。
  `ADMIN_TOKEN` がない環境では管理用の API はすべて 404。間違ったキーは認証と同じ回数制限。
- できること
  - 薬局の一覧：名前・コード・ログイン用メール・プラン（選択済みか）・登録日・最後のログイン・停止中か、
    直近30日の患者さんからの受付数・窓口照合の回数・未完了の受付数・未読のご意見数
  - 薬局の登録（名前・メール・プランは任意）→ 初回設定リンクと患者さん用リンクを表示
  - 初回設定リンクの再発行（14日間）
  - プランの変更（薬局の変更と同じ決まり：未完了の受付があるとAにはできない）
  - 停止・再開（停止するとログイン中の端末も終了。患者さんは送れない）
  - ご意見の一覧と「既読にする」
- 患者さんの情報（処方箋・問診）は管理画面に出さない。数だけ。

## 3. データ（migration 0009）
- `pharmacy_feedback (id, pharmacy_id, created_at, body, read_at)`
- `pharmacies.last_login_at`（ログインのたびに更新）

## 4. API
| | 認証 | |
|---|---|---|
| `POST /pharmacy/forgot` | なし | `{email}` → いつも `{ok:true}` |
| `POST /pharmacy/feedback` | 薬局 | `{body}` |
| `GET /admin/pharmacies` | 管理者キー | 一覧と数 |
| `POST /admin/pharmacies` | 管理者キー | 登録 |
| `POST /admin/pharmacies/:id/setup-link` | 管理者キー | 初回設定リンクの再発行 |
| `POST /admin/pharmacies/:id/plan` | 管理者キー | `{plan}` |
| `POST /admin/pharmacies/:id/disabled` | 管理者キー | `{disabled}` |
| `GET /admin/feedback`、`POST /admin/feedback/:id/read` | 管理者キー | |

## 5. 本番に出すとき（オーナーの OK のあとで）
1. `ADMIN_TOKEN` を作って `wrangler secret put`（キーはオーナーだけが持つファイルに保存）
2. リモート D1 に 0009 → worker → web（いつもの順番）
3. ガイド・案内・同意書（案）の「チラシは運営が送ります」を「受付画面から印刷できます」に直す
