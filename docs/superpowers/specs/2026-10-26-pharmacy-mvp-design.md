## 1. 目的となぜ今か

- これまでに作ったもの：患者さん向けの「処方箋ヘルパー」（rxhelper.jp・稼働中。処方箋の写真をやさしい言葉で説明、11言語、「薬局で見せるメモ」＝初回アンケートの項目と自由記述のAI翻訳）と、薬局向けの**デモ**（来局前に処方箋と問診が届き、在庫CSVとまとめて照合）。
- 薬剤師さんとのやりとり（2026年10月）で、次のことがはっきりした。
  - 在庫の確認は処方箋1剤ずつで手間。限定出荷も多い。
  - **レセコンのパソコンには何も入れられない**（社内規則）。受付用の別のパソコン・タブレットならインターネットにつながっている。
  - 外国人の患者さんの問診は翻訳ツールで対応している薬局が多い。ただし日本人の患者さんが中心の薬局が大多数。
  - 「データと現場の声を集めてから有料に」「検証研究として」と助言を受けた。
- 薬剤師さんの集まりで似たアプリの話題が出ている。カケハシの Pocket Musubi など、近いサービスはすでにある。**先に出すことより、実際に使ってくれる薬局を早く作ることが一番の守り**になる。デモから実際に動くサービスへ、ここで切り替える。

## 2. 誰のためのものか・お金の流れ

- **お金を払うのは薬局**（ユーザー決定）。在庫チェックの月額に、患者さん側の処方箋ヘルパーを含める。
- **その薬局の患者さんは無料**（ユーザー決定）。処方箋ヘルパーは月1〜2回しか使わないので、患者さんが月額を払う意味は薄い。薬局はどのみち患者さんから届くデータを受け取る必要がある。
- 患者さん向けの説明は「薬局が提供する服薬サポートのサービス」。**ポイント・割引・現金など金銭的な特典は付けない**（療担規則の患者誘引の禁止。2026年6月23日の厚労省事務連絡）。有料化の前に、保健所か薬剤師会に一度確認する。
- 既存の月額¥480プラン（有料会員1人）は**そのまま残す**（ユーザー決定）。今後の開発と宣伝は薬局連携に集中する。新規向けに¥480を売り続けるかは、有料化（2027年2月）のときに決める（Claude判断）。

## 3. ゴール・ノンゴール・アンチゴール

### ゴール（MVPでできること）
1. 患者さんが、薬局のQRコードから**会員登録なしで**、処方箋の写真と初回アンケートの答えを、その薬局に送れる。答えは母語でよい。
2. 薬局は受付用のブラウザで受け取り、**日本語・初回アンケートの順番**で答えを見られる。処方箋の写真とAIが読んだ薬の一覧も見られる。
3. 薬局は**自分の在庫CSV**と処方の薬をまとめて照合できる。CSVはそのブラウザの中だけで読み、サーバーには送らない。
4. 薬局から患者さんへ、返信（準備できました／疑義照会中／○時以降）と定型メッセージ・自由入力のメッセージを、**患者さんの言語で**届けられる。
5. 患者さんはアプリの画面で状態とメッセージを確認できる。希望した人にはメールでも知らせる。
6. データは「完了」または**7日**で自動的に消える。
7. 検証研究のために、時間の記録（届いた・開いた・返信した・完了した）が残る。中身（個人情報）は残さない。

### ノンゴール（MVPではやらない）
- レセコンとの連携、レセコンへの入力補助（QR・JAHIS形式の出力など）
- アレルギー・飲み合わせなどの**自動判定**
- 小分け（薬局どうしの譲渡）、発注、週末の予測、高額薬・薬価改定の機能
- LINE通知、プッシュ通知、ネイティブアプリ
- 薬局の検索・一覧（患者さんが薬局を選ぶ画面）
- 薬局への課金・請求の仕組み（検証研究中は無料）

### アンチゴール（動いても失敗とみなすこと）
- レセコンのパソコンに何かを入れさせる・つなぐこと
- 判断をアプリがしているように見えること（判断は薬剤師が行う）
- 患者さんに金銭的な特典を付けること
- 必要以上にデータを長く持つこと。在庫CSVをサーバーに送ること
- 患者さんに会員登録を求めて、送る前に離脱させること
- 日本人の患者さんしか来ない薬局にとって「多言語専用」に見えること

## 6. 機能

### 6.1 患者さん側（処方箋ヘルパー）

- **入口**：薬局ごとのQRコード／リンク（例：`https://rxhelper.jp/send?ph=<薬局コード>`）。開くと、その薬局名と「この薬局に処方箋を送る」画面が出る。
- **会員登録は不要**（ユーザー決定）。7日間の試用・月額の制限は、この流れには掛けない。
- **送る内容**
  1. 処方箋の写真（1〜2枚。カメラまたはアルバムから）。**電子処方箋の場合は「控え」（引換番号つき）の写真**でよい。薬局は写真の引換番号で自分の仕組みから処方を受け取る（Claude判断）
  2. 初回アンケートの答え：既存の「薬局で見せるメモ」の項目をそのまま使う（`lib/pharmacyCard.ts`。お薬手帳、身長・体重、ジェネリック、治療中の病気、アレルギー、副作用歴、他の病院・薬局の薬、市販薬、妊娠・授乳、生活習慣、よく摂取するもの、体質、食生活、苦手な剤形、メモ）。保存してあるメモがあれば下書きとして読み込む。
  3. 受け取りの希望時刻
  4. （任意）知らせてほしいメールアドレス
  5. 同意のチェック：選んだ薬局に送ること、AIが処方箋を読み・自由記述を翻訳すること（海外のサーバー）、薬局が確認したあと自動で消えること（確認されなくても7日で消える）
- **送ったあと**：アプリの画面に状態（確認しています → 準備できました／疑義照会中／○時以降にご用意）と薬局からのメッセージを、患者さんの言語で表示する（翻訳文の下に日本語の原文も表示）。受け取りのときは処方箋の原本と、お薬手帳かマイナ保険証を持ってくるよう案内する。
- **患者さんの識別**：会員登録の代わりに、送信時にサーバーが発行する推測できない受付番号（トークン）を端末に保存して使う（Claude判断）。
- **メール通知**：メールアドレスを入れた人にだけ、状態が変わったときに知らせる（ユーザー決定）。中身（薬の名前など）はメールに書かず、「薬局から返信がありました。アプリで確認してください」とリンクだけにする（Claude判断）。

### 6.2 薬局側（受付用のブラウザ）

- **ログイン**：薬局ごとのアカウント。検証研究の間は運営（Priamos）が発行し、薬局コードとQRも一緒に渡す（Claude判断）。
- **受信箱**：届いた順の一覧（受付時刻・患者さんの言語・受け取り希望・状態）。新しいものが届いたら画面上で分かる（数十秒ごとの自動更新で可）。
- **詳細**
  - 処方箋の写真（拡大可）
  - AIが読んだ薬の一覧（薬品名・用量・日数）。**参考情報**であり、判断は薬剤師が写真で確認する旨を常に表示
  - 初回アンケートの答え：**日本語・初回アンケートの順番**。自由記述は日本語訳＋原文
  - 「問診票（日本語）」の印刷
- **在庫の照合**
  - 薬局の在庫CSV（UTF-8／Shift_JIS）を**ブラウザの中だけで**読む。サーバーには送らない。読み込んだCSVはそのブラウザに保持してよい（毎回読み直さなくてよい）。在庫システムごとに列の並びや見出し行が違うため、**最初の読み込み時に「薬品名の列」「在庫数の列」を選べる**ようにする（既定は1列目＝薬品名、2列目＝在庫数）（Claude判断）。
  - 照合用の公的データ（`realdata.js`）は**内用薬のみ**。外用薬・注射薬などは「照合データなし（目で確認）」と表示する（Claude判断）。
  - 処方の薬ごとに「在庫あり／要確認／不足」と、必要量（1回量×回数×日数）と在庫数を表示する。
  - 名前の違う後発品・先発品は、厚労省の薬価基準・後発医薬品情報で同じ成分・規格として照合する（デモの `judgeGroup` と `realdata.js` を流用）。限定出荷・供給停止も表示する（厚労省の供給状況データ）。宣伝では「名寄せ」を売りにしない（薬剤師の助言）。
- **返信**
  - ボタン：準備できました／疑義照会中／○時以降にご用意（時刻を選ぶ）
  - 定型メッセージ：あらかじめ翻訳済みの文（「在庫が足りないため、一部のお薬は明日以降のお渡しになります」など。デモの5文を11言語に）
  - 自由入力：日本語で書くとAIが患者さんの言語に訳して送る。送る前に訳文を確認できる（Claude判断）
- **完了**：「完了」を押すとその受付のデータ（写真・答え）を消す。

### 6.3 運営側（Priamos）

- 薬局アカウントの発行・停止、薬局コードとQRの発行（最初は管理用のコマンドかスクリプトでよい。管理画面は不要）
- 検証研究の集計：受付件数、届いてから返信までの時間、完了までの時間（個人情報を含まない記録から出す）

## 7. データの流れ・保存・削除

1. 患者さんが送信 → Worker が受付を作り、写真を保存、薬局コードにひもづける。
2. Worker が処方箋の写真をAIで読み、薬の一覧（構造化データ）を作る。自由記述は日本語に翻訳する（既存の `/translate-memo` の仕組みを流用）。
3. 薬局が受信箱で開く・返信する → 状態とメッセージを保存。メールの希望があれば通知。
4. 患者さんの端末が受付番号で状態を取りに来る。
5. **削除**：薬局が「完了」を押したら、写真・答え・メッセージを削除。完了されなくても**受付から7日**で自動削除（定期実行）（Claude判断：7日）。
6. **残すもの**：時刻の記録（受付・初回表示・返信・完了）、言語、薬局コード、薬の数など、個人を特定しない数値だけ。
7. **在庫CSVはサーバーに来ない。**

保存先・暗号化・定期削除の具体的なやり方は builder に任せる（例：写真は R2、受付は D1、削除は Cron Trigger）。データの置き場所（国内か）も検討し、同意画面とプライバシーポリシーの記載と一致させること。
