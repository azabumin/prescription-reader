# 設計書：薬局プラン A・B（窓口処方箋の在庫照合／外国籍患者の初回問診）

作成日：2026-11-01　／　前提：`2026-10-26-pharmacy-mvp-design.md`（MVP、本番稼働中）
承認：オーナー（2026-11-01、チャットで確認）

## 1. 目的となぜ今か

10/29 の薬剤師様のご意見（「機能を分けて契約したい」「登録薬局が少ないうちは患者さんが送れない」）を受け、
薬局だけで使える **A**・**B** に分けて、Aのみ／Bのみ／A+B で提供できるようにする。
登録薬局を増やすことが先で、患者さんの送信を広く案内するのはその後（方針メモ `ご意見を受けた方針_A・Bプラン_ja.md`）。

## 2. プラン

| プラン | 薬局の画面 | 患者さんの送信 |
|---|---|---|
| **A** 在庫・欠品・出荷調整チェック | 窓口照合（新規）＋在庫CSV | 受け付けない |
| **B** 外国籍の患者さんの初回問診 | 受信箱・問診票（日本語）・返信 | 受け付ける（薬の読み取りはしない） |
| **AB** セット | すべて | 受け付ける（今の本番と同じ） |

- 1つのシステムの中で、薬局ごとにプランを持つ（アプリを分けない）。
- 既存の薬局（テスト薬局 n3eg3txvqn を含む）は **AB** のまま。

## 3. ゴール・ノンゴール・アンチゴール

**ゴール**
- 薬局ごとのプラン（A／B／AB）を運営側が登録時に決め、あとから変えられる。
- プランA：窓口で受けた処方箋を撮影または取り込み → AIが薬剤名を読み取り → 在庫CSVと照合して表示・印刷。
- プランB：今ある受付の流れ（QR送信・受信箱・問診票・返信）をAの部分なしで使える。
- 画面で隠すだけでなく、Workerでもプランを確認して断る。

**ノンゴール**
- 料金・契約・課金（決まっていない）。
- 薬局側ガイドPDF・デモ動画（この後の別作業。A/Bの画面ができてから作る）。
- 近隣薬局との在庫照合（扱わない）。
- スキャナのPDF取り込み（JPEG/PNGの画像のみ）。

**アンチゴール（動いても失敗とみなすこと）**
- 窓口照合で処方箋の画像や読み取り結果がサーバーに残る。
- AだけやBだけの薬局で、使えない機能が画面に出る／APIで使えてしまう。
- 既存の AB 薬局の動き（受信箱・照合・返信）が変わる。

## 4. 機能

### 4.1 データと運営

- マイグレーション 0007：`pharmacies.plan TEXT NOT NULL DEFAULT 'AB'`、値は `'A' | 'B' | 'AB'`（CHECK制約）。
- `worker/scripts/new-pharmacy.mjs --plan A|B|AB`（省略時 AB）。プランAでは患者さん用リンクを出さない。
- `worker/scripts/set-pharmacy-plan.mjs --code <薬局コード> --plan A|B|AB [--remote]`：プランの変更。
- 運営側の利用数は `intake_events` に `event = 'walkin_check'` の行で残す（個人データなし。`intake_ref` は毎回の乱数のハッシュ、`drug_count` = 読み取った薬の数）。

### 4.2 ログインとプランの受け渡し

- `POST /pharmacy/login` の応答に `plan` を含める。
- `GET /pharmacy/me` → `{ name, code, plan }`。ログイン済みの端末（セッション30日、ブラウザに保存）は
  プラン情報を持っていないので、受付画面を開くたびにこれで最新のプランを受け取り、保存し直す。
  運営側がプランを変えても、次に開いたときに反映される。

### 4.3 Workerでの制限

| 経路 | A | B | AB |
|---|---|---|---|
| `GET /p/pharmacy`, `POST /intakes`（患者さん） | 404（「薬局が見つからない」＝送信画面が既に扱うエラー） | 可 | 可 |
| `/pharmacy/intakes…`, `/pharmacy/templates`, `/pharmacy/translate-preview` | 403 `{error:'plan'}` | 可 | 可 |
| `POST /pharmacy/check`（窓口照合） | 可 | 403 `{error:'plan'}` | 可 |
| 送信後の処理 `processIntake` | — | 薬の読み取りを省く（AI費用の節約）。`drugs_status = 'skipped'` | 今と同じ |

### 4.4 プランA：窓口照合 `/pharmacy/check`

- 固定ルート（静的ホスティングのため動的セグメントなし。`lib/staticRoutes.test.ts`）。
- 画像は最大2枚。「撮影する」（タブレットのカメラ）と「画像を選ぶ」（スキャナのJPEG/PNG）の両方を置く
  （撮影かスキャナかは薬剤師様に確認中なので、どちらでも使えるようにする）。
  送信画面と同じく長辺1568px・JPEGに縮小（`lib/sendLogic.ts` `longEdgeResize`）。
- 「読み取る」→ `POST /pharmacy/check`（薬局セッション必須）→ Workerは既存の `extractDrugs` で薬のリストを返す。
  - **何も保存しない**：受付の行は作らない。画像はAIに渡したら捨てる。残すのは 4.1 の件数の行だけ。
  - 1薬局1日300回まで（KV）。超えたら 429。
  - AIが失敗したら 502 → 画面は「読み取れませんでした。もう一度撮影するか、原本で確認してください。」
- 照合は端末の中で：保存済みの在庫CSVと既存の `matchDrug` で、受信箱の詳細画面と同じ表を出す
  （表は共通の部品にして両方の画面で使う）。在庫CSVはサーバーに送らない（今と同じ）。
- 印刷できる（ボタン類は印刷しない）。「次の処方箋へ」で画像と結果を消す。
- 個人情報の扱い：窓口の処方箋は患者さん本人ではなく薬局がAI（Anthropic社・米国）に送るため、
  画面に「画像は薬の読み取りにだけ使い、保存しません（米国のAIサービスに送信します）」と表示し、
  その端末で初めて使うときに1回だけ確認のチェックをもらう（端末のブラウザに記録）。
  薬局との契約・同意書の文言は別途オーナーが判断する。

### 4.5 プランB

- 受信箱・問診票・返信は今のまま。受付画面から在庫CSVの欄と窓口照合を隠す。
- 受信箱のカードの「AI読み取り」表示、詳細画面の「処方の内容と在庫」欄を隠す（写真と問診票は出す）。

### 4.6 受付画面（`/pharmacy`）

- A：見出し「窓口の処方箋チェック」、「窓口の処方箋を照合する」ボタン、在庫CSV。受信箱は出さず、取得もしない。
- B：受信箱のみ。
- AB：受信箱＋在庫CSV＋「窓口の処方箋を照合する」ボタン。

## 5. 制約

- Expo 57 の静的書き出し（GitHub Pages）。薬局の画面は日本語のみ・メイリオ優先。
- Workerのテストは外部通信なし（AIは関数の差し替えで試す。`processIntake` と同じやり方）。
- 本番作業（リモートのマイグレーション 0007、Worker と Web の公開）はオーナーがその場で確認してから。

## 6. ついでに直すもの（触る箇所に含まれるため）

- 詳細画面：`card_json` に欠けた項目があると問診票（JapaneseCard）で落ちる → 既定値で補ってから表示。
- `intake_events.drug_count` が書かれていない → 読み取り成功時に、その受付の `received` 行へ薬の数を書く。窓口照合の行にも書く。

## 7. builder に任せること（設計者の判断）

- 403 のエラーコード名（`plan`）、日次上限 300、窓口照合の文言。
- `drugs_status` に `'skipped'` を足す（プランBで読み取りを省いた受付。あとでABに変えても「読み取り中」のまま止まらない）。
- 画像の幅・高さが取れないブラウザ（Web では 0 になることがある）は画像を読み込んで測ってから縮小する。
